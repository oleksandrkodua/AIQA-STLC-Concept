# Курс для команды: AI-ассистент в QA с нуля (набросок)

STATUS: DRAFT v0.1, 2026-10-07. Набросок. Не согласован. Формат: один урок
(две презентации-части + короткая практика) в неделю, ~45 минут. Язык: английский (перевод по запросу).

## Кому и зачем

Аудитория: инженеры QA, которые не работали с AI-ассистентами и не знают терминов. Цель курса:
через 13 недель человек сам объясняет, что такое CLAUDE.md, скилл, субагент, хук и eval,
знает, что из этого у нас включено, а что нет, и умеет проверить результат ассистента.

Чего курс НЕ делает: не учит программировать, не обещает процент автоматизации, не заменяет
политику AI клиента (`policy/ai-usage-policy.md` в статусе DRAFT; до согласования с командой и
клиентом правила использования агентов остаются предложением).

## Как устроен каждый урок (шаблон)

1. Один тезис на слайд, аналогия из QA-жизни.
2. «Спроси зал» (2–3 вопроса с голосованием поднятой рукой): сначала предсказать, потом показать.
3. Демо на безопасных данных (без клиентских материалов; пока доступа нет, демо на публичных сайтах).
4. Домашнее задание с проверкой, которую можно сделать без экспертизы (команда, видимый результат,
   источник, число). Если проверки нет, это сказано на слайде.
5. Слайд «Что у нас включено, а что нет» с честными статусами.

Фактический статус на 2026-10-07: хуки и права в статусе DRAFT и не активны; evals написаны, не запускались;
агенты выключены в MVP; код автоматизации из Архіва не портирован. Курс не должен выдавать черновик за
работающую систему.

## План уроков

Каждый урок = одна встреча ~45 минут, две части (A и B), каждая отдельная презентация на 10–12 слайдов. Урок 0 (~15 минут) идёт перед Уроком 1.

| # | Тема | Главный вопрос | Ключевые термины | Домашняя проверка |
|---|---|---|---|---|
| 0 | Зачем это QA | Почему верификация и требования дороже генерации? | рынок, ценность проверки, «AI даёт справку, не вердикт» | Назвать одну свою задачу, где проверка важнее генерации |
| 1 | Карта: что есть что | Из чего состоит работа с ассистентом? | LLM, токен, ассистент, агент, CLAUDE.md, rules, skill, субагент, hook, eval, MCP, плагин | Нарисовать карту своими словами и показать, где у нас лежит каждая деталь (список путей) |
| 2 | Где работаем: Claude Desktop, CLI, плагин VS Code | Чем отличаются разрешённые инструменты и какой когда брать? | Desktop, CLI, плагин VS Code (плюсы и минусы); у нас не используются: веб claude.ai, плагин Chrome | Выбрать инструмент под три учебные задачи и объяснить выбор |
| 3 | Контекст и токены | Почему ассистент «забывает» и стоит денег? | окно контекста, context rot, `/context`, `/compact`, `/clear`, plan → clear → implement | Открыть `/context` в своей сессии, записать, что занимает окно |
| 4 | Недетерминизм и галлюцинации | Почему нельзя верить уверенному тону? | температура, утверждать правила, а не формулировки, evidence | Задать один промпт 3 раза, выписать, что изменилось |
| 5 | Инструкции: CLAUDE.md, AGENTS.md, rules | Что куда писать? | always-on vs по пути (`paths:`), 100 строк, «онбординг для нового сотрудника» | Найти в репозитории правило и сказать, на какие файлы оно действует |
| 6 | Скиллы | Чем скилл отличается от промпта? | SKILL.md, description как триггер, progressive disclosure, evals у скилла | Предсказать, какой скилл сработает на 5 фразах (skill-selection) |
| 7 | Агент, субагент, скилл: что когда | Кому отдавать работу? | цикл plan-act-observe, свой контекст, возврат выжимки, STOP/ESCALATE/CONTINUE | Разобрать 3 сценария: скилл, субагент или ничего |
| 8 | Права и хуки | Как удержать недетерминированную модель в рамках? | allow / ask / deny, PreToolUse, PostToolUse, exit 2, fail-open | Прочитать hooks README и назвать, что хук НЕ останавливает |
| 9 | Evals | Откуда мы знаем, что это работает? | критерии заранее, 3 прогона, PASS / FAIL / INCONCLUSIVE, sabotage matrix, verification-log | Прочитать одну строку verification-log и пересказать её |
| 10 | MCP, плагины, моды | Как ассистент получает руки? | MCP vs CLI, секреты, плагин, маркетплейс, моды (непроверено у нас) | Объяснить, почему у нас список MCP пустой |
| 11 | Данные и безопасность | Что нельзя делать никогда? | prod запрещён, секреты, PII, инъекция через текст тикета | Найти в тикете (учебном) текст-инструкцию и показать, что он не выполнен |
| 12 | Цикл QA с AI | Где человек, а где ассистент? | требование → кейсы → ручной прогон → readiness → тест → ревью, оракул, Iron Law | Пройти цикл на одном учебном кейсе |
| 13 | Мобайл и измерения | Что считать результатом? | эмулятор ≠ устройство, SKIP ≠ PASS, ROI = экономия / время ревью, baseline | Посчитать ROI одной сессии по формуле, указав, что оценка, а что измерено |
| B | Бонус: кейс «цепочка с человеческими гейтами» | Как собрать цепочку, где человек проверяет каждый шаг? | skills + references + golden dataset, гейты, «нет источника, нет вывода» | Найти гейт в кейсе и сказать, что он ловит |

Порядок можно менять после первого пилота. Уроки 8–9 лучше давать после того, как хуки и evals
реально прогнаны; до этого они учат «как будет», а не «как есть», и это нужно сказать вслух.

## Словарь (рабочие определения для урока 1)

Источник определений: общие понятия Claude Code и материалы конференции (`knowledge/register.md` R-10, R-13, утверждения спикеров не проверялись). Поведение функций в конкретной версии Claude Code на
машинах клиента не проверено.

| Термин | Простыми словами | Аналогия | Где у нас |
|---|---|---|---|
| LLM | Модель, которая по тексту предсказывает следующий токен | Стажёр, который прочёл весь интернет и не видел ваш проект | вне репозитория |
| Токен | Кусок текста, за который платят и который занимает окно | «Слог» для счётчика | счётчик `/usage` |
| Контекст (окно) | Всё, что модель видит прямо сейчас | Стол, на котором помещается ограниченная стопка бумаг | сессия |
| Ассистент | LLM + инструкции + инструменты + память + цикл | Стажёр с рабочим местом | Claude Desktop / Code |
| Агент | Ассистент, который сам повторяет «план → действие → проверка» и меняет состояние (файлы, тикеты) | Стажёр, которому дали ключи | выключены в MVP (`.claude/agents/README.md`) |
| Субагент | Отдельный работник со своим окном контекста, получает задачу, возвращает короткую выжимку | Коллега в соседней комнате, оставляет записку | не используем |
| CLAUDE.md | Файл, который ассистент читает в начале каждой сессии | Документ для онбординга нового сотрудника | `CLAUDE.md` (<100 строк) |
| AGENTS.md | Общее соглашение об инструкциях для разных AI-инструментов (по материалам конференции) | Тот же онбординг, но для разных стажёров | нет |
| Rules | Правила в отдельных файлах; часть действует только для путей (`paths:`) | Правила цеха: «в этой комнате только в касках» | `.claude/rules/` |
| Skill | Папка с SKILL.md: описание-триггер и инструкции, подгружаются, когда нужны | Рецепт, а не просьба «приготовь что-нибудь» | `.claude/skills/` |
| Hook | Команда, которая запускается на событии (до/после действия) и может его остановить | Турникет на входе | `.claude/hooks/` (DRAFT) |
| Permissions | allow / ask / deny: разрешить, спросить, запретить; deny сильнее allow | Список допусков | `settings.draft.json` (не активен) |
| Eval | Заранее написанные задания с ожидаемым результатом, прогоняются несколько раз | Контрольная для ИИ | `evals/` |
| MCP | Стандарт подключения внешних инструментов с типизированными вызовами | Розетки и провода | список пуст (`.mcp.json`) |
| Плагин / мод | Пакет расширений (скиллы, хуки, агенты) | Набор инструментов в коробке | пользовательские моды в базу не входят (см. `optional/mods/`) |

Расширенный разбор «модель, харнес, агент» и частых путаниц (скилл или хук, скилл или сабагент, effort или thinking) лежит в `training/materials/model-harness-agent-glossary.md` (английский, DRAFT). Там помечено расхождение: заметка называет агентом любой «Claude» в чате, а урок 1 различает ассистента и агента; выбрать одно определение нужно владельцу курса.
