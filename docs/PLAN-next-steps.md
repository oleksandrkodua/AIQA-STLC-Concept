## Жёсткие правила (не нарушать)
- Защищённые файлы: `CLAUDE.md`, `.claude/**` (rules, hooks, settings), `plugins/qabase/**` (skills), `policy/**`, `evals/**`, утверждённый контекст. Менять только после одобрения QA Lead. Сначала предложение: файл, изменение, причина, последствия; остановиться.
- Не переименовывать и не перемещать файлы ради единообразия. Не добавлять каталоги и инструменты без подтверждённой нужды. Не выдумывать статусы и содержимое.
- Метки: VERIFIED FACT / EVIDENCE-SUPPORTED INFERENCE / ASSUMPTION / UNKNOWN / NOT TESTED / NOT RUN.
- `main` защищена: только PR с зелёным `validate`. Один PR на одно изменение. Коммиты без строки Co-Authored-By. Push и `gh pr create/merge` делает пользователь (из сессии Claude они блокируются хуком).
- Перед PR: валидатор на чистом экспорте (`git ls-files` в пустую папку, затем `python3 evals/validate_repo.py`). На 2026-11-13: 267 passed (на 2026-11-10 было 264). Локальный запуск видит git-ignored файлы и даёт другое число.
- Внешний материал сначала в `knowledge/register.md` по `knowledge/INTAKE.md` (одно источник = одно мнение), правилом он становится только через предложение QA Lead.
- В корне лежит чужой неотслеживаемый `handoff-istqb.md`: не трогать и не коммитить.
